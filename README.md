# Tabletop Copilot

Советник по D&D 5e (SRD, редакция 2014): во что превратиться друиду в этой
обстановке и какие заклинания взять с учётом того, что уже умеет партия.

Главный принцип — **модель не может предложить нелегальный вариант**, потому что
работает не по памяти, а по списку, отобранному детерминированными правилами из
настоящего каталога. Цифры в ответе берутся из каталога, а не из текста модели.

## Экономия запросов

По умолчанию **модель не вызывается вообще**: рейтинг с цифрами считается
детерминированно, мгновенно и бесплатно. Объяснение словами — отдельное
действие, и только оно тратит запрос.

Ответы кэшируются по ключу, в котором нет ничего личного, поэтому кэш общий:
запрос друга с похожим раскладом попадает в ваш, и расход на человека с ростом
числа пользователей падает, а не растёт. Сверху суточный бюджет — общий и на
каждого игрока: при исчерпании инструмент не падает, а переходит в режим
«только цифры».

## Установка

```bash
uv sync --group dev
uv run python -m tools.sync_catalog   # разовая загрузка каталога SRD
```

Каталог тянется один раз (98 зверей и 319 заклинаний), дальше всё работает
офлайн — за столом ничего не зависит от доступности API.

### Веб-интерфейс

```bash
uv run streamlit run apps/ui.py
```

### Телеграм-бот

```bash
uv sync --group dev --extra bot
# TELEGRAM_BOT_TOKEN от @BotFather в .env
uv run python -m apps.bot
```

Бот работает через long polling: публичный адрес, вебхуки и туннели не нужны,
запускается прямо с ноутбука. Им можно делиться — у каждого игрока свой
персонаж, партия собирается по коду-приглашению.

Команды: `/me друид 6`, `/party` (лист отряда), `/party create`,
`/party join КОД`, `/spells`, `/fight goblin 4, ogre`, свободный текст —
обстановка для выбора формы.

### Объяснения от модели

```bash
uv sync --group dev --extra llm
# GEMINI_API_KEY в .env
```

Без ключа приложение работает: просто без текстовых объяснений.

## Как устроено

Три слоя, и модель только на последнем:

1. **Правила** — чистые функции: CR-лимит вайлдшейпа по уровню, запрет полёта
   до 8 уровня и плавания до 4, принадлежность заклинания списку класса.
   Отсекают всё нелегальное.
2. **Эвристика** — числовой скор кандидата: урон, живучесть, уместная в этой
   обстановке скорость, совпадение местности; у заклинаний — какой роли не
   хватает партии.
3. **Модель** — получает 3–8 кандидатов с готовыми цифрами и объясняет выбор.

## Лист партии

Показывает, что отряд умеет и чего ему не хватает: кто владеет какими
спасбросками, какие роли закрыты, какие типы урона доступны. Самое ценное —
дыры в спасбросках: партия без владения Мудростью ложится от Hold Person
целиком, и узнать это лучше при подготовке.

Роли считаются по заклинаниям, до которых персонажи реально дотягиваются на
своём уровне, а не по таблице «класс → что приносит».

## Боевая математика

Урон можно считать против конкретного противника, а не в вакууме. Точный AC
игроку знать неоткуда, поэтому спрашивается то, что видно за столом
(«кольчуга», «латы»), и подставляется типичное значение.

Разница существенная: у бурого медведя в статблоке 19 урона за раунд, а против
латника выходит 8.4. И порядок меняется — против доспеха форма с бонусом атаки
+5 обгоняет форму с +4, хотя по костям та бьёт сильнее.

## Опасность боя

Отвечает на вопрос «драться или бежать»: сколько раундов нужно, чтобы убить
противников, и сколько вы продержитесь. Обычные калькуляторы складывают опыт за
головы и сверяются с таблицей — отсюда их дурная слава.

Стороны считаются с разной уверенностью, и это показывается явно: **противники
точно по статблокам, партия приблизительно** по классу и уровню. Оценка партии
намеренно занижена — кастеры считаются по заговорам, а не по слотам, — чтобы на
вопрос «бежать?» ошибиться в сторону осторожности.

Сверено с тем, что знает любой игрок: партия 1 уровня против огра —
«смертельно», 5 уровня против молодого красного дракона — «смертельно»,
11 уровня против него же — «по силам».

Не учитываются способности со спасброском (дыхание дракона), лечение, контроль
и отступление, поэтому это нижняя граница опасности.

Отсюда и гарантия: нелегального варианта нет во входных данных модели, а значит
предложить его она не может.

Расширяется двумя механизмами: классы описаны таблицей данных, а не ветками
кода, а каждая фича — модуль, реализующий один протокол, плюс строка
регистрации. Зарегистрированный советник сам появляется и в боте, и в вебе.

## Данные

[Open5e](https://open5e.com), документ `srd-2014` (SRD 5.1, открытая лицензия).

Паладин не поддерживается: в этих данных его заклинания не размечены —
`Divine Favor` помечен жреческим, а `Branding Smite` не имеет классов вовсе.

**Изобретатель** (и подкласс Артиллерист) добавлен вручную: он из Tasha's, а
не из SRD, поэтому его механика описана в `core/class_profiles.py`, а список
заклинаний задан ключами. Из 66 заклинаний класса в SRD есть 57 — остальные
пришли вместе с классом из Tasha's и в открытый документ не попали.
